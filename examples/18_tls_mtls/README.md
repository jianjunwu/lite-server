# 18. TLS / mTLS (P5-1)

Serve inference over **HTTPS with mandatory client certificates** (mutual TLS)
and demonstrate **live certificate rotation** — no server restart required.

[中文版](README_zh.md)

## What this example shows

- `server.tls_cert_path` / `tls_key_path` — the HTTP listener speaks TLS.
- `server.mtls_ca_path` — when set, clients **must** present a certificate
  signed by this CA (mTLS). Handshakes without a client cert are rejected by
  the TLS layer itself.
- `tls_min_version: "1.3"` — only TLS 1.3 is accepted.
- **Hot rotation** — the server watches the PEM files (10-second content poll,
  plus instant `SIGHUP` on Unix). Replace the files and new connections
  immediately use the new certificate; a failed reload keeps serving the old
  one.

## Layout

```
certs/          — generated by setup.sh (CA, server, client keypairs)
model_repo/
  tls_echo/1/   — echo model (input × 2)
server.yaml     — TLS + mTLS enabled
```

## Running

```bash
# Generate certificates (idempotent):
bash setup.sh

# Start the server:
lite-server serve --config server.yaml
```

## Verify

```bash
# 1. mTLS request — client certificate required:
curl --cacert certs/ca.crt --cert certs/client.crt --key certs/client.key \
     -s -X POST https://localhost:8000/v2/models/tls_echo/infer \
     -H 'Content-Type: application/json' -d '{"input": 21}'
# => {"output": 42}

# 2. Without a client certificate the TLS handshake fails:
curl --cacert certs/ca.crt -s -X POST https://localhost:8000/v2/models/tls_echo/infer \
     -H 'Content-Type: application/json' -d '{"input": 21}'
# => curl: (56) ... (no client cert presented)

# 3. Rotate the server certificate WITHOUT restarting the server:
openssl req -newkey rsa:2048 -keyout certs/server.key -out /tmp/rot.csr \
    -nodes -subj "/CN=localhost-rotated"
openssl x509 -req -in /tmp/rot.csr -CA certs/ca.crt -CAkey certs/ca.key \
    -CAcreateserial -out certs/server.crt -days 3650 \
    -extfile <(printf "subjectAltName=DNS:localhost,IP:127.0.0.1")
kill -HUP <server-pid>   # optional: instant reload (otherwise ≤10s poll)
rm /tmp/rot.csr
# New connections now present the rotated certificate (check the peer CN).
```

## Notes

- Client identity (certificate subject) is recorded in request context for
  access logs / audit. API-key auth on top of mTLS is configured separately
  via `policies.auth` — see example 17.
- The gRPC listener has its own independent TLS settings under `grpc.*`.
- TLS is mutually exclusive with a UDS (`unix:` host) bind.
